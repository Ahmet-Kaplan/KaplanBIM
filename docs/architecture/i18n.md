# Internationalisation

## What it owns

| Where | What |
|---|---|
| `packages/bim-ui/src/i18n/` | `createI18n`, `I18nProvider`, `useT`, `format.ts` (locale numbers/dates), `persistence.ts`, `domain.ts`, `prose.ts` |
| `packages/bim-ui/src/language-toggle.tsx` | The switcher |
| `packages/bim-editor/src/editor/i18n/` | `useEditorTranslate`, `translateFor`, `englishOnly`, `withValues`, `editorResources` |
| `packages/*/locales/tr/*.json`, `apps/*/locales/tr/*.json` | Turkish, one file per namespace, beside the code that shows it |
| `tools/i18n/` | The review-bundle generator and the prose extractor |
| `docs/i18n/glossary.md` | **Binding terminology.** Not documentation: a contract |

## The contract

1. **English is the `defaultValue` at the call site**, never a key alone:
   `t('ribbon.merge', 'Merge')`. There is no `en.json`. A reader of the code sees the
   English; a missing Turkish key falls back to it and never renders `ribbon.merge`.
2. **Turkish lives beside the code that shows it**, in that package's `locales/tr/`.
   Namespaces are declared once, in `MUTINY_NAMESPACES` (`bim-ui/src/i18n/index.ts`).
   A namespace that ships but is never merged into a provider is dead weight — see
   "goes wrong" below.
3. **The provider is the host's job.** `bim-ui` and `bim-editor` *consume* the context;
   they never create an instance. The hosted app (`apps/mutinybim-web/client/editor-language.tsx`)
   and the demo (`packages/bim-editor/demo/entry.tsx`) own it, and both merge
   `editorResources` **and** `schedulesResources`.
4. **`{{n}}`, never `{n}`.** i18next's default delimiters are double braces. A single-brace
   placeholder is not interpolated — it renders literally, in both languages.
5. **Turkish takes no plural suffix after a number.** `{{n}} eleman`, never
   `{{n}} elemanlar`. Where English needs one/other, key both and give Turkish the same
   string twice; that is correct, not lazy.
6. **Unit symbols are never translated** (`kVA`, `CFM`, `mm`, `Pa`, `°C`); unit *names*
   are (`Amps` → Amper). Numbers localise: `12.345,67` in `tr`, `12,345.67` in `en`.
7. **Terminology comes from the glossary**, and a new term goes into the glossary **in the
   same commit** that first uses it. §9 of the glossary records the twenty conflicts
   (`Panel` → pano vs panel, `Branch` → branşman vs dal, `Run` → hat vs çalıştır,
   `Owner` → Sahip vs İşveren) and those are not negotiable per-string.
8. **A translator never reaches for a global.** Functions that emit text take a `Translate`
   parameter. Where a function can emit a placeholder, that parameter is **required**, so
   omission is a compile error rather than a screenshot of braces.

## How it goes wrong

The tells, in the order they actually bit us:

- **English silently changed.** Moving a JSX string into a `t()` default is a copy, not an
  edit. We once reworded "total of pipes" to "pipes · total" while "wrapping" it, and no
  test noticed because the test asserted against the new default. *Tell:* a diff in which
  the same line has both `-` and `+` with different English.
- **A caption that never got a `t()` at all.** The review tool counts *written* keys, so an
  English caption with no `t()` is invisible to it — "0 missing" reads true while the
  screen is half English. This is why the negative-space guard exists.
- **A `{{…}}` placeholder on an `englishOnly` path.** `englishOnly` is
  `(_key, english) => english` unless it wraps `withValues`; a placeholder-bearing default
  routed through a non-interpolating translator prints `{{name}}` on screen. It shipped
  twice. *Tell:* any `t()` whose default contains `{{` and whose translator can be
  `englishOnly`.
- **A local alias of the translator.** `const tr = t ?? words` — both scanners matched only
  `t(` and `tr(`, so four keys were invisible to every guard and never translated. The
  follow-up trap is the same alias surviving in a new file. Both extractors now accept
  `t|tr|translate`; keep it that way.
- **A namespace merged nowhere.** `schedulesResources` existed, was tested, and was imported
  only by tests; the app's provider passed `editorResources` alone, so 360 keys were dead
  at runtime. *Tell:* a `Resources` export whose only importers are under `__tests__`.
- **A translated noun inside an English sentence.** `` `Collapse ${title}` `` with a Turkish
  title renders "Collapse Özellikler". Key the verb too, or pass the whole composed label.
- **A parameter that changes the meaning.** `Some count` vs `count of {{relationship}}`: a
  slot whose value is itself a word drags its language along. Slots carry numbers and unit
  symbols; anything else belongs in the sentence.
- **A term drifting to a fourth synonym.** `öğe` appeared 40 times as a third word for
  element/item, against §0.1 of the glossary. *Tell:* a noun the glossary does not list,
  used more than twice.
- **Turkish that asserts the wrong cause.** A generic fallback must be true for *every*
  sentence that reaches it. `in_use` once said "still used elsewhere" for a lock, a pinned
  sheet item and a full panel — Turkish that confidently sends the reader to the wrong
  screen is worse than English.
- **A singular imperative in a sentence.** §0.7: sentences use the polite plural
  (`…seçin`, `…tıklayın`), buttons stay singular (`Seç`, `Ekle`). Mixed register on one
  card reads as machine translation.

## Where the guard is

| Guard | Catches | Blind to |
|---|---|---|
| `packages/bim-ui/__tests__/i18n-parity.test.ts` | `tr`/`en` parity, key-as-value, single-brace placeholders **in `tr` and in English defaults**, prose-slot rules; pins its own corpus | a caption with no `t()` at all |
| `packages/bim-ui/__tests__/i18n-glossary.test.ts` | §8 plural-after-number, `space`→`alan`, `sheet`→`tablo`; cause-neutrality of generic sentences | term drift to an unlisted synonym (`öğe`) |
| `packages/bim-editor/__tests__/i18n-negative-space.test.ts` + `helpers/editor-visible-english.ts` | user-visible English **outside** a translator: JSX children (including the literal segments around interpolations), `<title>`, `aria-label`/`title`/`placeholder`, `toast`/`setError`/`notify`/`onRefused`/`setStatus` arguments, undo labels, single-word captions; **and an unkeyed twin of a keyed sentence** | what its roots do not cover — `OUTSIDE_STAGE_4` names them |
| `packages/bim-editor/__tests__/helpers/editor-source-captions.ts` | per-key **site counts**: keying one of two call sites back to a literal fails | a key with no pin (`SITES[key] ?? 1`) |
| `tools/i18n/review-bundle.mjs` (`npm run i18n:review`) | coverage: every written key with its English and Turkish, `⚠️ eksik`, `⚠️ boş değer`, orphans | keys never written |
| `docs/i18n/glossary.md` §9 | the twenty conflict resolutions | anything nobody wrote down |

A guard is worth only what it can fail on. Before trusting one, plant the violation it
claims to catch and watch it go red — every guard in the table above has been tested that
way, and three of them were found to be claiming coverage they did not have.

## Adding a third language

The runtime is ready: `MUTINY_LANGUAGES`, `isMutinyLanguage`, and `createI18n` take a
language, and `LanguageToggle` renders from an options list. The **tooling is not**: the
guards, the review bundle and the extractors hardcode `locales/tr`. A third language needs
those parameterised first, or it ships unguarded.
